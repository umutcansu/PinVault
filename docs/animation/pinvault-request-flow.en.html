Glossary: the terms used in this animation
Public key, private key
A key pair generated together. The public key can be given to anyone; the private key is kept secret and is used to sign or to decrypt.
ANDROID_ID
The ID number Android assigns to the device. It is not secret. The device reports it itself; on its own it does not count as proof.
APK
The installation file of an Android app. Everyone installs the same one.
ARC (attestation reason code)
The 8-character code of an attestation verdict. Even when the phone is not told the rejection reasons, this code is sent; the admin looks the code up in the dashboard to see the reasons.
Attestation
The phone measuring itself (root, emulator, debugger, hooking, clone, app integrity), signing the result with its Keystore key and presenting it to the server. The server decides: an app that passes receives a short-lived PinVault-Token (and the new signed list, if it changed), one that fails gets no token. The pin list is not secret; the token is the real lock. The same idea Approov works on.
Declared vs proven device identity
The ANDROID_ID the phone writes during enrollment is only its claim. If the admin bound the token to that identity, or the hardware attestation of the key confirmed it, the identity counts as proven. The certificate can act on behalf of that phone (opening a token_mtls file, changing the encryption key) only if the identity is proven.
CA (certificate authority)
The party that signs certificates. The PinVault server has two CAs of its own: one signs device certificates, the other signs the recovery port certificate.
Client ID (identity)
The device's name on the server, for example tablet-07.
Config API
The server address the app gets its pin list and files from. It is either TLS or mTLS.
CSR (certificate signing request)
The device's "give me a certificate for this public key" request. It proves it owns the key with a signature made with that key.
Audit log
The record the server keeps of who did what, and when.
Digital signature
A computation that proves who some data came from and that it was not changed. Only the owner of the private key can make it; anyone can verify it.
Hardware attestation
A statement signed by the phone's secure hardware: "this key was generated on this phone, for this app, and cannot leave it". From it the server knows the key came from a real phone.
Screen lock
The phone's PIN, pattern, password or fingerprint. The hardware uses the key of a screen-lock-protected file only after this lock is unlocked.
Host
The name of the server the app connects to, for example api.example.com.
Port
The address number the server listens on: 8090, 8091, 8092, 8093. The numbers are the ones the demo app assumes; the code defaults are 8080, 8081 and 8083.
Keystore
Android Keystore, the phone's key vault. A private key generated in it cannot be exported; it can only be asked to sign.
mTLS
TLS where both sides show a certificate: the server proves its identity to the phone and the phone proves its identity to the server.
Nonce
A single-use, 2-minute random challenge the server gives out for attestation. The phone signs it together with its report; the same signed report cannot be sent twice.
P12
An encrypted file that carries a certificate together with its private key.
Pin
The SHA-256 hash of a certificate's public key: the certificate's fingerprint.
PinVault-Token
A 5-minute signed ticket (HS256 JWT) the server gives to a phone that passed attestation. The library puts it in the header of every request to the app's own servers; that server verifies the signature itself without asking PinVault.
Rejection policy
The admin's choice for each attestation signal: reject (does not pass), warn (passes, a warning is logged) or ignore (not checked). Set per config API.
Certificate
A signed document stating who a key belongs to: like an ID card.
Expiry time (expiresAt)
The last moment the signed pin list is valid. The server gives 24 hours by default; the phone will not connect with a list past that time.
SSL pinning
The phone talking only to a certificate whose pin it recognises.
TLS
An encrypted connection (https). At the start of the connection the server shows its certificate.
Token
A random, secret string the server generates. An enrollment token is single-use; a file token is for one file and one device.
Vault
The part of PinVault that distributes files.
Managed trust roots
Root CA pins carried in the signed pin list (trustRoots). For a host that has no pin, the phone accepts a certificate whose chain the platform validates and whose root is in this list: the authority is your signed list, not the phone's own CA store.
